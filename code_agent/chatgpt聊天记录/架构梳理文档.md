# code_agent 架构梳理文档

> 按 **"功能N：函数1→函数2→函数3"** 结构深度梳理 `code_agent` 文件夹的完整调用链路。

---

## 整体架构总览

```
功能1: Web API 入口         (agent_web_api.py)
功能2: 插件调度系统          (plugins/)
功能3: 具体插件执行          (plugins/code_*.py + vulnerability_detection.py)
功能4: Aider 桥梁           (aider_runner.py)
功能5: Prompt 构造引擎       (completion_prompt_agent.py)
功能6: 项目解析与知识图谱     (rag/)
功能7: CLI 前端             (cli/)
功能8: Web UI              (webui/)
功能9: VS Code 扩展         (vscode_server.py)
```

## 功能2：插件调度系统

> **文件夹**: `plugins/` — 插件系统的核心基础设施。

### 2.1 自动注册

```
plugins/__init__.py
└── _import_all_plugins()
    └── pkgutil.iter_modules(__path__)           ← 自动扫描所有子模块
        └── importlib.import_module(module_name)
            └── 触发 @register_plugin 装饰器
                └── registry.register(plugin())   ← 注册插件实例
```

### 2.2 注册中心

> **文件**: `plugins/registry.py`

```
FeatureRegistry (单例)
│
├── register(plugin: FeaturePlugin)
│   └── _plugins[name] = plugin
│
├── get(name: str) → FeaturePlugin | None
│   └── _plugins.get(name)
│
├── list_plugins() → List[FeatureMetadata]
│   └── [p.metadata for p in _plugins.values()]
│
└── get_schemas() → Dict[str, List[Dict]]
    └── 遍历所有插件，提取 config_schema 序列化
```

### 2.3 调度器

> **文件**: `plugins/dispatcher.py`

```
ExecutionDispatcher
│
└── dispatch(context: ExecutionContext)
    ├── registry.get(feature_name)               ← 查找插件
    ├── plugin.validate(config, files)           ← 校验配置
    │   └── 返回错误信息 或 None
    └── 按 ExecutionMode 分发:
        │
        ├── ExecutionMode.AIDER
        │   └── _execute_aider(plugin, context)
        │       ├── yield start 事件
        │       └── for log in plugin.execute(context):
        │           └── yield ndjson_event()       ← 逐行流式输出
        │           └── _infer_status(log)         ← 推断执行状态
        │
        ├── ExecutionMode.DIRECT
        │   └── _execute_direct(plugin, context)
        │       ├── yield start 事件
        │       └── for item in plugin.execute(context):
        │           ├── PluginResult → yield done 事件
        │           └── str → yield log 事件
        │
        └── ExecutionMode.HYBRID
            └── _execute_hybrid(plugin, context)
                ├── yield start 事件 (Phase 1: Analysis)
                ├── for item in plugin.execute(context):
                │   ├── {"phase":"analysis_done"} → 分析完成事件
                │   ├── PluginResult → 最终完成事件
                │   └── str → log 事件
                └── (Phase 2: Remediation 由插件内部控制)

ndjson_event(payload) → str
└── json.dumps(payload, ensure_ascii=False) + "\n"
```

### 2.4 基类定义

> **文件**: `plugins/base.py`

```
枚举类型:
├── ExecutionMode: AIDER | DIRECT | HYBRID
└── ConfigFieldType: TEXT | TEXTAREA | SELECT | SWITCH | FILE

数据类:
├── ConfigField                          ← 配置字段定义
│   ├── name, label, type
│   ├── required, default
│   ├── placeholder, help_text
│   └── options, accept, multiple
│
├── FeatureMetadata                      ← 插件元信息
│   ├── name, label, description
│   └── icon, execution_mode
│
└── ExecutionContext                     ← 执行上下文
    ├── project_dir, target_files
    ├── instruction, model, api_key
    ├── feature_config, uploaded_files
    └── symbol, completion_type, prefix

类:
├── PluginResult                         ← 执行结果
│   ├── success, message, log
│   ├── files_modified, report
│   └── artifacts
│
└── FeaturePlugin (ABC)                  ← 插件抽象基类
    ├── metadata: FeatureMetadata        ← 抽象属性
    ├── config_schema: List[ConfigField] ← 抽象属性
    ├── validate(config, files) → str|None
    ├── execute(context) → Generator     ← 抽象方法
    └── preview(context) → str
```

### 3.3 代码修复插件 (CodeRepairPlugin)

> **文件**: `plugins/code_repair.py` | `@register_plugin` | `ExecutionMode.AIDER`

```
CodeRepairPlugin
│
├── config_schema:
│   ├── repair_type (SELECT: bug_fix/compile_error/test_failure/safe_refactor)
│   ├── failure_log (TEXTAREA, 可选)
│   ├── extra_context (TEXTAREA, 可选)
│   └── allow_refactor (SWITCH, 默认 false)
│
├── preview(context)
│   ├── _build_repair_instruction(context)
│   │   ├── REPAIR_TYPES[repair_type]
│   │   ├── _bool_config(allow_refactor)
│   │   └── 拼接: 硬性要求 + 失败日志 + 额外上下文 + 交付标准
│   └── preview_prompt()
│
└── execute(context)
    ├── _build_repair_instruction(context)
    └── run_aider_stream()
```

**修复指令模板结构**:
```
1. 优先定位根因，不要只掩盖症状
2. 保持现有公开接口、文件结构和调用约定
3. 只修改与本次问题直接相关的代码
4. 不要引入新的第三方依赖
5. 修改后保持项目现有代码风格
6. 允许/禁止无关重构或格式化
```

### 3.4 漏洞检测插件 (VulnerabilityDetectionPlugin)

> **文件**: `plugins/vulnerability_detection.py` | `@register_plugin` | `ExecutionMode.HYBRID`

```
VulnerabilityDetectionPlugin
│
├── config_schema:
│   ├── scan_scope (SELECT: targets/project)
│   ├── severity_threshold (SELECT: low/medium/high/critical)
│   ├── rule_profile (SELECT: default/c_cpp/web)
│   ├── auto_fix (SWITCH, 默认 false)
│   ├── max_findings (TEXT, 默认 30)
│   ├── context_lines (TEXT, 默认 2)
│   └── extra_instruction (TEXTAREA, 可选)
│
├── preview(context)
│   └── 返回配置摘要文本
│
└── execute(context)                           ← HYBRID 模式
    │
    ├── Phase 1: 分析阶段
    │   ├── _collect_files(project_dir, target_files, scan_scope)
    │   │   ├── scope=targets → 取 target 文件
    │   │   └── scope=project  → os.walk + 扩展名过滤
    │   │
    │   ├── _scan_files(files, threshold, rule_profile, max_findings, ...)
    │   │   ├── _active_rules(rule_profile)
    │   │   │   ├── "default" → PATTERN_RULES 全量
    │   │   │   ├── "c_cpp"   → 仅 C/C++ 相关规则
    │   │   │   └── "web"     → 仅 Web 后端相关规则
    │   │   │
    │   │   └── for 每个文件 × 每条规则:
    │   │       └── _match_rule(file, project_root, rule_id, rule, context_lines)
    │   │           ├── re.search(pattern, line)      ← 正则匹配
    │   │           ├── _is_likely_finding(rule_id, lines, idx)
    │   │           │   ├── cwe-78: 检测 shell=True / os.system / subprocess
    │   │           │   ├── cwe-89: 检测 SQL 拼接 (f-string / + / .format)
    │   │           │   ├── cwe-22: 检测 ../ 路径穿越
    │   │           │   └── cwe-134: 检测 printf 格式化字符串
    │   │           ├── _extract_context(lines, idx, context_lines)
    │   │           └── _matched_pattern(patterns, line)
    │   │       └── _sort_findings(findings)
    │   │
    │   ├── _build_report(findings, project_dir, threshold, rule_profile, count)
    │   └── yield {"phase": "analysis_done", "report": report}
    │
    ├── Phase 2: 修复阶段 (仅 auto_fix=True 时)
    │   ├── _find_fixable_target_files(project_dir, target_files, findings)
    │   ├── _build_remediation_instruction(base_instruction, findings, report, extra)
    │   │   └── 构造: 安全修复要求 + 漏洞报告 + JSON 发现 + 用户补充 + 额外约束
    │   └── run_aider_stream(fixable_files, remediation_instruction)
    │
    └── yield PluginResult(success, message, log, report, files_modified, artifacts)
```

**漏洞检测规则表** (`PATTERN_RULES`):

| rule_id | 名称 | 严重度 | 置信度 | 适用语言 | 检测模式 |
|---------|------|--------|--------|---------|---------|
| cwe-120 | 缓冲区溢出 | high | medium | C/C++ | `strcpy(`, `strcat(`, `sprintf(`, `gets(` |
| cwe-134 | 格式化字符串 | high | high | C/C++ | `printf(变量名...)` |
| cwe-22 | 路径穿越 | medium | low | 多语言 | `../`, `open(`, `readFile(`, `File(` |
| cwe-89 | SQL 注入 | high | medium | Web 后端 | `SELECT/INSERT/UPDATE/DELETE` + 拼接 |
| cwe-78 | 命令注入 | high | medium | Web 后端 | `os.system(`, `subprocess.run/Popen`, `Runtime.exec(` |

┌─────────────────────────────────────────────────────────────────┐

│   生成完整 Aider 执行上下文 (核心编排函数)                         │
├─────────────────────────────────────────────────────────────────┤
│   ensure_aider_installed()         ← 检查 aider 是否在 PATH     │
│   normalize_project_dir()                                       │

│   resolve_api_key()                                              │

└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────┤

┌─────────────────────────────────────────────────────────────────┐
│ run_aider_cli()                   ← 同步执行 (CLI 使用)          │
├─────────────────────────────────────────────────────────────────┤

│   subprocess.run(aider_command, check=True)                     │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│ preview_prompt()                  ← 仅预览 prompt，不执行        │
├─────────────────────────────────────────────────────────────────┤
│   build_aider_context_and_command(no_pretty=True)               │
│   返回: init_log + final_instruction                            │
│   清理临时 prompt 文件                                           │

### 4.3 工具函数

```
normalize_project_dir(project_dir) → str
├── 空值 → DEFAULT_PROJECT_DIR (当前工作目录)
└── Path.expanduser().resolve()

normalize_target_files(target_files, project_dir) → List[str]
├── str → [str]; None → []
└── 相对路径 → 基于 project_dir 拼接绝对路径

normalize_file_path_for_parser(file_path, project_dir) → str|None
└── 绝对路径 → 相对路径 (相对于 project_dir), 分隔符统一为 "/"

detect_provider(model) → str
├── model.startswith("deepseek/") → "deepseek"
├── model.startswith("openrouter/") → "openrouter"
└── 默认 → "deepseek"

resolve_api_key(api_key) → (str, str)
└── 参数 → DEEPSEEK_API_KEY → OPENROUTER_API_KEY → OPENAI_API_KEY → 空

write_prompt_file(content) → str
└── tempfile.NamedTemporaryFile(suffix=".txt", encoding="utf-8")

build_aider_command(edit_files, model, api_key, prompt_file, no_pretty, dry_run) → List[str]
└── ["aider", *files, "--model", model, "--message-file", prompt_file,
     "--no-gitignore", "--map-tokens", "0", "--yes-always",
     "--no-fancy-input", "--no-auto-commits", (+ --dry-run, + --no-pretty)]

decode_process_line(raw_line: bytes) → str
└── 编码候选: utf-8 → gb18030 → cp936 → 系统编码 → utf-8(replace)

mask_command_for_log(aider_command, model) → str
└── 遮蔽 API Key: provider=sk-***

build_subprocess_env() → dict
└── PYTHONIOENCODING=utf-8, PYTHONUTF8=1, NO_COLOR=1
```

## 功能5：Prompt 构造引擎

> **文件**: `completion_prompt_agent.py` — 根据项目语义图谱构造 LLM prompt。

### 5.1 类初始化与项目加载

```
CompletionPromptAgent
│
├── __init__()
│   ├── project_parser = None         ← CProjectParser / JavaProjectParserTS
│   ├── searcher = None               ← 语义搜索器
│   ├── parse_res = None              ← 项目解析结果缓存
│   ├── language = "c"
│   └── proj_dir = None
│
├── _infer_language(file_path, explicit_language) → str
│   ├── explicit_language in {"c", "java"} → 直接使用
│   ├── file_path.suffix == ".java" → "java"
│   └── 默认 → "c"
│
└── load_project(proj_dir, language)
    ├── language == "java"
    │   ├── JavaProjectParserTS()             ← rag/java/java_project_parser_ts.py
    │   └── parse_res = parser.parse_dir(proj_dir)
    └── language == "c"
        ├── CProjectParser()                   ← rag/c/preprocess.py
        ├── parse_res = parser.parse_dir(proj_dir)
        └── searcher = parser.proj_searcher
```

### 5.2 主入口 build_prompt

```
build_prompt(request: Dict) → str
│
├── 解析 request 字段:
│   ├── project_dir, file_path, user_instruction
│   ├── symbol, completion_type, prefix
│   └── language
│
├── _infer_language(file_path, request.language)
│
├── 条件加载: (proj_dir 变更 or parse_res 为空 or language 变更)
│   └── load_project(proj_dir, language)
│
├── language == "java"
│   └── _build_java_completion_prompt()
│       ├── _get_file_info(file_path)
│       │   └── parse_res[normalized_path]
│       ├── 提取 symbol_candidates (Class/Interface/Enum/Method/Field...)
│       ├── symbol/prefix 过滤 + 排序截断 (≤40)
│       ├── 从 parse_res 全局收集相关定义 (≤20)
│       └── 拼接 Java 专用 prompt 模板
│
└── language == "c"
    ├── _infer_symbol_from_instruction(instruction)
    │   └── re.search(patterns, instruction)     ← 中文正则提取
    │       ├── r"补全\s+(\w+)\s*函数"
    │       ├── r"完善\s+(\w+)\s*(?:函数|实现)?"
    │       ├── r"实现\s+(\w+)\s*(?:函数)?"
    │       └── ...
    │
    ├── _infer_completion_type(instruction, symbol)
    │   ├── "函数体/实现/补全/完善" + symbol → "function_body"
    │   ├── "成员/字段/->/." → "member"
    │   ├── "变量" → "variable"
    │   ├── "函数签名/声明/函数名" → "function"
    │   ├── "类型/typedef/struct/union/enum" → "type"
    │   └── 默认 (有 symbol) → "function_body"
    │
    └── 按 completion_type 分发:
        ├── "member"        → _build_member_completion_prompt()
        ├── "variable"      → _build_variable_completion_prompt()
        ├── "function"      → _build_function_completion_prompt()
        ├── "function_body" → _build_function_body_completion_prompt()
        ├── "type"          → _build_type_completion_prompt()
        └── fallback        → _build_fallback_prompt()
```

### 5.3 各补全类型 Prompt 构造器

```
_build_member_completion_prompt()
├── _get_file_info(file_path)
├── _find_type_of_symbol(file_path, symbol)
│   └── 从 info["rels"] 中查找 "Typeof" 关系
├── _find_struct_like_by_type(file_path, type_name)
│   └── 在当前文件/全局查找 Struct/Union/Enum
├── _collect_struct_members(struct_name)
│   └── 遍历全局，收集 info["in_struct"] == struct_name 的成员
├── _filter_prefix(member_names, prefix)
├── _safe_get_prompt4names() → searcher.get_prompt4names()
├── _find_owner_file(struct_name) → 查找符号定义文件
└── _build_aider_edit_requirements([额外规则])

_build_variable_completion_prompt()
├── _get_file_info(file_path)
├── _iter_symbols_in_file(file_info)
│   ├── type == "Variable" + in_function → 局部变量
│   └── type == "Variable" + not in_struct/not in_function → 全局变量
├── _safe_get_prompt4names(file_path, {""})
└── _build_aider_edit_requirements([额外规则])

_build_function_completion_prompt()
├── 遍历所有文件, 筛选 Function 类型
├── 按 symbol/prefix 匹配
├── 排序: (非同文件优先, 行号升序, 名称升序)
└── _build_aider_edit_requirements([额外规则])

_build_function_body_completion_prompt()
├── _get_file_info(file_path)
├── _safe_get_prompt4names({symbol})        ← 目标函数当前定义
├── _iter_symbols_in_file() → 同文件其他函数参考 (≤10)
├── 全局查找 symbol 的其他声明/定义 (≤10)
└── _build_aider_edit_requirements([额外规则])

_build_type_completion_prompt()
├── 遍历 Struct/Union/Enum/Variable 类型
├── _safe_get_prompt4names() 获取结构体上下文
└── _build_aider_edit_requirements([额外规则])

_build_fallback_prompt()
├── _safe_get_prompt4names(file_path, {""})
└── _build_aider_edit_requirements()
```

### 5.4 工具函数汇总

```
_get_file_info(file_path) → Dict|None
└── parse_res[file_path.replace("\\", "/")]

_iter_symbols_in_file(file_info) → Generator[(name, info)]
└── yield from file_info.items() (跳过空名称)

_find_symbol_info(file_path, symbol) → (name, info)|None
├── 精确匹配: symbol in file_info
└── 后缀匹配: name.endswith(f".{symbol}")

_find_type_of_symbol(file_path, symbol) → str|None
└── info["rels"] 中 item[-1] == "Typeof" → item[0]

_find_struct_like_by_type(file_path, type_name) → str|None
├── 清理指针/引用/const 修饰符
└── 在当前文件/全局匹配 Struct/Union/Enum

_collect_struct_members(struct_name) → List[str]
└── 全局收集 info["in_struct"] == struct_name

_filter_prefix(names, prefix) → List[str]
└── [x for x in names if x.split(".")[-1].startswith(prefix)]

_safe_get_prompt4names(file_path, names, only_def, enable_docstring) → str
└── searcher.get_prompt4names() (异常返回错误信息)

_find_owner_file(symbol_name) → str|None
└── 遍历 parse_res，找到第一个包含 symbol_name 的文件

_build_aider_edit_requirements(extra_rules) → str
└── 6 条通用规则 + 额外规则 → 拼接为 "【执行要求】" 块
```
